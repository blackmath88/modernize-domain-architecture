01 · Why everybody suddenly cares about JEV

Decision work is not the same as language generation.

If the task is “pick the best legal next move”, a frontier LLM may be an extremely expensive way to implement a classifier.

The JEV attraction

Fast, cheap, calibrated decisions create a separate “decision layer” inside agent systems. The deeper idea is bigger than JEV: shrink the surface that needs generative reasoning.

02 · Start with the messy bit

Human intent is fuzzy.

“Modernize this app” can mean framework upgrade, cloud migration, CVE cleanup, containerization, rearchitecture, or all of them. This is a legitimate place for language understanding.

03 · Modernize does not ask Claude to rediscover everything

Assessment is already typed.

In our PhotoAlbum run, .NET AppCAT produced machine-readable findings: rule IDs, file locations, target-specific severity, effort, frameworks, languages and tools. The raw analysis itself took about one second.

04 · The middle layer

Facts become an executable plan.

Modernize loads assessment results, merges rulebook constraints, then emits both plan.md for humans and tasks.json for execution. The task layer is structured enough to drive routing.

05 · Not one giant agent

Specialists are routed by task type.

Java upgrades, .NET-to-Azure work, security/CVE remediation and rearchitecture are delegated to different executors. The orchestrator is explicitly closer to a router than a universal doer.

06 · Where determinism becomes non-negotiable

The compiler gets the last word.

Build, tests, CVE scanning and deployment checks close the loop. The LLM may propose a change; software proves whether it survives contact with reality.

08 · So where is the value?

The scarce asset may not be the model.

Cheap to repeat

Semantic compile

Version detection, code-shape classification, compatibility checks, legal transitions, dependency ordering, validation.

Expensive but flexible

Large LLM

Ambiguous intent, architecture trade-offs, unsupported edge cases, synthesis across incomplete business context.

High upfront value

Domain knowledge

Migration recipes, compatibility facts, known-safe transformations, framework conventions and operational constraints.

Irreplaceable input

Human policy + goals

“Keep RabbitMQ.” “No public endpoints.” “Use PostgreSQL.” “Minimize operational change.” These are not discoverable from code alone.

09 · The critique is not “Microsoft did it wrong”

They did the architecture. The question is who owns the knowledge.

①

Vendor truth vs domain truth

“Windows Auth is incompatible with ACA” is a domain/target fact. “Move to Azure service X” can be a vendor-preferred path. Those are not the same layer.

②

Closed expertise compounds

If the best migration knowledge is trapped inside one agent stack, every other agent must rediscover, reverse-engineer or pay to access the same domain expertise.

③

Big-model overreach

Once inputs and legal moves are already typed, using a frontier model for every routing or selection decision may add cost and variance without adding much intelligence.

Domain fact

Spring Boot 2 API X is incompatible with Spring Boot 3.

community / upstream
Legal transformation

Replace X with Y; update dependency Z; run validator Q.

machine-executable
Vendor package

For Azure target A, prefer service B and identity pattern C.

vendor-owned
Organization policy

Use PostgreSQL, Managed Identity, no Kafka, region restrictions.

human-governed
Agent decision

Choose among legal paths when constraints are incomplete or genuinely ambiguous.

probabilistic
10 · The abstraction

Machine-executable domain packages.

Package stable domain expertise so that Copilot, Codex, Claude, a local model, or no model at all can consume the same substrate. The agent becomes a client of the domain, not its owner.

# community/java-spring/domain.yaml
schema: medp/v0
name: community/java-spring
version: 1.4.0

requires:
  - community/java-core@^3
  - community/jakarta@^2

capabilities:
  observe: [java.version, spring.version, api.usage]
  transform: [java.upgrade, spring.upgrade, javax.to-jakarta]
  validate: [java.compile, java.tests]
Existing precedent

OpenRewrite already looks like part of this future.

OpenRewrite uses Lossless Semantic Trees and composable recipes for framework migrations and refactoring. Community projects already publish migration recipes for ecosystems such as Apache Camel, Wicket, AWS SDK, Axon, Jenkins and others.

That means the transformation layer does not have to be invented from zero. The opportunity is to make the harness, packaging, provenance and agent boundary explicit.

The thesis

The agent is a client of the domain.

Microsoft Modernize shows that serious agentic software already depends on typed analyzers, task contracts, domain specialists and deterministic verification. The next question is whether that domain expertise should be portable infrastructure.

Build software with LLMs not software out of LLMs
