# Machine-Executable Domain Packages

**Hypothesis:** Stable expertise can be exposed as portable software capabilities rather than repeatedly reconstructed in model context.

A package can combine observations, rules, legal transitions, transforms, explanatory knowledge, validators, tests, and compatibility metadata. A harness or agent queries the package for supported moves and evidence; it does not treat the model as the package's source of truth.

The success condition is stronger than identical generated code: two compatible clients should derive the same legal transitions, constraints, blockers, and validation criteria from the same observations and package versions.

MCP is one possible port. CLI and library access should remain possible so that the package is not coupled to one agent protocol.
